# BBGDDG 阅读理解与文献笔记设计

日期：2026-10-05。状态：用户于 2026-10-07 授权按设计实施并上传 GitHub。

## 目标与已确认需求

供用户自己阅读论文和教科书，重点解决内容理解和笔记整理。核心流程是阅读 → 提问 → 形成自己的理解 → 保存笔记 → 复习时回到原文。

用户已确认：笔记支持自己撰写与摘取 AI 解释；以文献组织，主题知识为辅；在原文上创建的笔记直接关联原文并跳转；提供独立笔记页和分屏；侧面板可收起到边栏；AI 问答和笔记共用侧面板，通过标签切换。

## 阅读与复习布局

## 页面结构与导航（补充整理）

保留“先进入项目，再打开文献”的主线。项目是学习资料夹，可按课程、学科或研究课题建立；不将首页改成全部文献列表。

| 页面 | 职责与主要内容 | 主要去向 |
| --- | --- | --- |
| 首页：我的项目 | 搜索、新建项目、最近项目和全部项目；展示项目名称、简短描述、文献数量及最近访问时间 | 进入项目工作区 |
| 项目工作区：文献 | 默认显示文献与文件夹，支持导入、项目内搜索、文件夹及子文件夹整理、移动文献 | 打开文献阅读页 |
| 项目工作区：笔记 | 分为项目笔记与按文献归组的文献笔记 | 打开项目笔记或文献笔记页 |
| 阅读页 | 原文为主，右侧切换 AI 问答和笔记，面板可收起 | 文献笔记复习页、返回项目 |
| 文献笔记页 | 文献内笔记整理与复习，原文分屏定位 | 对应原文、返回阅读或项目 |
| 项目笔记页 | 学习计划、跨文献总结等，不强制归属单篇文献；支持引用项目内多份文献 | 引用文献、返回项目 |
| 全局设置 | AI 完整配置、显示偏好和数据管理 | 返回原页面 |

首页左侧提供所有项目、最近项目和设置，侧栏可收起；标题与搜索、新建项目放在顶部，最近项目与全部项目为主体。统一使用“我的项目”称呼，删除等低频操作放入更多菜单。

项目页左侧展示返回所有项目、项目名称、文献和笔记入口，底部提供项目设置；顶部提供当前页面标题、项目内搜索、紧凑 AI 入口和导入文献。标注归入对应文献的笔记体验，对话历史在 AI 面板中访问，全文搜索通过顶部入口访问。调整入口不删除原有标注或对话数据。

AI 完整配置在全局设置中；首页和项目页保留紧凑入口，显示当前工具/模型与可用状态，展开后可切换并查看用量。未配置时显示“配置 AI”。阅读页在 AI 标签内提供工具/模型切换；笔记复习页也可展开问答。入口共用现有 AI 配置，不因页面切换产生互相矛盾的当前模型状态。

项目笔记和文献笔记共用笔记编辑能力，但归属明确：从阅读页创建默认属于当前文献，项目笔记从项目入口创建。文献移动文件夹后，笔记与原文关联保持稳定。

典型路径：我的项目 → 线性代数 → 教材文件夹 → 教材阅读 → 选区提问 → 摘入文献笔记 → 文献笔记复习 → 点击关联回原文。另一路径：项目 → 笔记 → 学习计划或跨文献总结。

尚待细化：项目文献采用列表或封面卡片；阅读页是否保留可收起的项目文献目录。此前推荐目录默认收起，用户本轮要求先整理，因此暂不将该项视为确认。现已进入实施阶段，布局选择暂沿用现有文献列表；项目文献目录仍留待后续细化。

## 阅读与复习详细交互

阅读模式以 PDF 为主，侧面板切换 AI 问答与笔记。复习模式进入独立的文献笔记页，以笔记为主，侧面板展示对应 PDF。两个模式使用同一份笔记数据，保留阅读位置、笔记浏览位置、对话与未提交草稿。

侧面板支持调整宽度、收起成窄边栏、再次展开。收起、展开和切换标签不得丢失草稿或中断正在进行的回答。窄窗口采用主区与可展开覆盖面板，保留同样的标签和收起入口，避免不可用的三列布局。继续使用现有中文深色视觉风格。

## 提问流程

选中文字后点击“问 AI”，展开问答标签，附带选中原文及 PDF 页位置。支持直接输入问题和“解释这段”“解释概念”“逐步讲解推导”快捷提问；无选区时默认针对当前文献。保留已有 AI 配置与用量提示。

选区是提问重点；解释需要的上下文可从当前文献检索补充，并在回答中展示可核实的引用。文献没有提供的信息需明确说明，不把补充知识伪装成原文结论。这里是对现有选区限定策略的拟议调整，需在实施时同步服务端范围规则。

## 笔记内容与来源

每条笔记具有标题、可编辑 Markdown 正文、所属文献、可选标签、创建与更新时间。正文支持公式；用户原文与 AI 摘录均可编辑。AI 回答或选中的回答段落通过“摘入笔记”进入草稿，由用户编辑后保存；同时保留来源消息关联，不把 AI 回答当作经过核实的事实。

原文笔记保存选中片段及稳定锚点。锚点包括文献标识、文件内容标识、PDF 页序号、归一化位置矩形、选中文字及可用文字偏移。页码以 PDF 页序号为准，避免与教材印刷页码混淆。一条笔记允许多个原文关联，分别可点击定位。

选区问答摘录沿用该提问的原文锚点。整篇文献问答仅保留文献与来源消息关联；回答中的有效引用可单独添加为原文关联，不默认宣称整条回答来自某一段。

复习页默认按原文位置排序，无锚点的总结排在末尾并按创建时间排序；提供文献内标题、正文搜索和标签筛选。暂不自动推断章节，用户可在标题和标签中记录章节。

## 原文定位

点击原文关联时，在原文分屏中定位对应 PDF 页和位置，并临时标亮。优先使用保存的坐标与锚点；缩放后按归一化坐标恢复，不依赖 AI 重找原文。

文件内容改变时，不使用旧坐标冒充准确位置；尝试文字匹配并标为待确认。无法匹配则保留笔记，提示关联失效。PDF 不可访问时展示明确提示。独立总结或疑问的“AI 查找原文”属于后续增强：展示候选片段与页码，经用户确认才添加关联，不阻塞本期直接跳转流程。

## 现有能力与改动范围

已检查 ReaderPage、NoteEditor、PdfViewer、ChatPanel 和数据库初始化代码：现有阅读页具备 PDF 与工具面板、选区提问、标注、文献笔记和引用页跳转；独立 NoteEditor 已支持 Markdown 与公式。阅读侧面板目前按条件挂载，需要调整以保留标签切换后的状态。现有普通笔记与标注分别保存，需要建立统一复习视图与笔记锚点关联。

实施边界：复用 PDF 阅读器和现有问答服务；布局组件管理面板状态；笔记服务管理正文、标签、原文锚点和消息来源；定位逻辑由阅读器处理。共享逻辑服务于阅读与独立笔记页，避免两套笔记实现。

数据升级前备份，保留现有笔记与标注。已有文献笔记保持归属；已有带注释标注可在统一笔记视图中呈现，保留原标注标识，不自动合并不同正文、不删除历史数据。新增锚点与来源关联须校验项目和文献归属；删除引用标注不应删除已保存的笔记锚点副本。

## 验证与交付标准

1. 阅读选区可发起提问；选区位置可沿用到 AI 摘录笔记。
2. 用户可独立写笔记、摘取整条或部分回答、编辑后保存；保存失败保留草稿并提供重试。
3. 切换标签、收起面板、切换阅读与复习模式保留草稿、会话和位置；进行中的回答保持连续。
4. 点击原文笔记精确跳回并标亮，重复文字、缩放和跨页选区不误定位。
5. 独立笔记页和阅读侧面板同步同一份已保存数据；公式正常展示，键盘可操作标签和展开入口。
6. 旧数据升级后仍可阅读、编辑和定位；文件缺失、内容变化及关联失效有明确反馈。

验证采用数据库迁移与归属校验测试、定位测试，以及覆盖阅读 → 提问 → 摘录 → 复习 → 跳回原文的浏览器端流程。优先使用模拟 AI，不消耗真实 API 用量。

## 移动版路线图

用户明确要求将移动版落地提上日程。将其纳入正式路线图，在桌面版页面结构与笔记关联设计落地时同步考虑移动适配，不推迟到桌面全部功能完成以后才研究。以下是建议的阶段安排，不代表已经选择发布平台、同步服务或上线日期。

### 阶段一：共用基础与技术验证

桌面主线实施时同步抽离阅读、问答、笔记与锚点的数据和状态逻辑；验证手机和平板 PDF 渲染、触控选区、长文献内存占用、公式显示、文件导入及持久保存。目标平台已确定优先 iPhone / iPad；明确具体测试设备，再比较移动网页/PWA 和原生应用封装路线，避免默认 Electron 可直接部署到手机。

现有服务依赖本机 Node、SQLite 及桌面命令行 AI 工具。移动版需要明确服务和存储在哪里运行；不能只缩小网页就宣称可以独立使用。技术验证至少对比连接桌面服务与独立移动运行的成本、可用性和限制。移动端不能默认使用桌面 CLI 登录状态，AI 需有实际可达的服务/API 路径。

### 阶段二：移动最小可用版本

范围：项目 → 文件夹 → 文献 → 阅读 → 提问 → 保存文献笔记 → 复习 → 原文定位；同时支持项目笔记。沿用已确认的项目优先组织方式。

手机以单主区为默认，原文、AI、笔记通过抽屉或标签切换，保存切换前的位置和草稿；不强制三栏。平板在空间足够时提供可调整、可收起的分屏。横竖屏和软键盘出现时不得遮挡提问输入或保存操作。选区操作改为适合触控的入口，不能依赖鼠标悬停。

### 阶段三：跨设备连续使用与发布

在确定数据方案后实现文献、笔记、锚点和阅读进度的跨设备使用。先比较手动导入导出与自动同步；若采用同步，明确文件存储、身份认证、冲突处理、离线修改和密钥管理。原文关联通过稳定文献标识与内容标识保持，不能依赖桌面绝对文件路径。

验证无网阅读与笔记保存、联网 AI 错误反馈、恢复联网后的行为，以及目标平台实际安装/启动流程，再决定测试分发或正式发布。AI 云端问答继续明确文献内容发送范围。

### 排期与验收

下一轮实施计划单列移动技术验证任务，和桌面布局/笔记数据结构规划一起启动；移动 MVP 在阅读与笔记共用接口稳定、运行与存储路线验证通过后推进。具体日期和工作量在目标平台与技术路线明确后估算。

验收以真实目标设备完成整条阅读与复习流程为准，包含长教材、触控选区、原文精确定位、后台恢复、草稿保持和本地数据重启后仍可读取；桌面浏览器缩窄窗口只能作为适配检查，不能替代移动落地验收。
